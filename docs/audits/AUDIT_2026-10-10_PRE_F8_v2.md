### 3. Análisis de Riesgo: `audit_events_insert_authorized`
- **Definición en BD:** La política de INSERT sobre `public.audit_events` posee la cláusula `WITH CHECK (true)` para el rol `authenticated`.
- **Qué PUEDE hacer un usuario malintencionado:** Al tener `WITH CHECK (true)`, cualquier usuario autenticado puede emitir un `INSERT` en `audit_events` asociando el evento al `business_id` de otro negocio, falsificando el historial de auditoría o saturando la tabla con registros basura (ataque de polución / tampering de log).
- **¿Puede leer lo escrito por otro negocio?** **NO**. La política de lectura `SELECT` sobre `audit_events` exige estrictamente que el usuario sea el `owner_id` del negocio (`businesses.owner_id = auth.uid()`). No hay fuga de datos, pero sí vulnerabilidad de integridad de auditoría.

### C7. Restricción de Extracción Única Activa por Documento
* **Archivo afectado:** `supabase/migrations/20261011000002_unique_active_extraction.sql`.
* **Cambio exacto:**
  ```sql
  -- 1. Desactivar duplicados existentes conservando la extracción más reciente
  WITH ranked AS (
    SELECT id, ROW_NUMBER() OVER (PARTITION BY document_id ORDER BY extracted_at DESC) as rn
    FROM public.document_extractions WHERE is_active = TRUE
  )
  UPDATE public.document_extractions
  SET is_active = FALSE
  WHERE id IN (SELECT id FROM ranked WHERE rn > 1);

  -- 2. Crear índice único parcial
  CREATE UNIQUE INDEX IF NOT EXISTS uq_document_extractions_active
    ON public.document_extractions(document_id)
    WHERE is_active = TRUE;
  ```
* **Justificación técnica:** Garantizar a nivel de motor de BD que un documento jamás pueda tener dos extracciones activas simultáneas.
* **Riesgo:** Bajo (se resuelve primero el caso de `prueba4.pdf`).
* **Plan de Rollback:** `DROP INDEX IF EXISTS uq_document_extractions_active;`.
* **Esfuerzo estimado:** 15 minutos.
